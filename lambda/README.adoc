= Docling Lambda Handler
:toc:
:toc-placement!:

AWS Lambda handler for document conversion using Docling.

toc::[]

== Overview

This Lambda function converts documents stored in S3 using the same Docling conversion logic as the HTTP server. It supports multiple input formats (PDF, DOCX, images, etc.) and multiple output formats (JSON, Markdown, HTML, YAML, text, doctags).

== Request Format

[source,json]
----
{
    "files": [
        {
            "region": "us-east-1",
            "bucket": "my-bucket",
            "key": "documents/file.pdf"
        }
    ],
    "output_format": "json",
    "additional_formats": ["markdown", "html"],
    "options": {
        "ocr": {
            "engine": "rapidocr",
            "force_full_page_ocr": false
        }
    }
}
----

=== Fields

[cols="1,1,1,3"]
|===
|Field |Type |Required |Description

|`files`
|array
|Yes
|Array of S3 file references to convert (max 10 files)

|`files[].region`
|string
|No
|AWS region for the S3 bucket. Defaults to Lambda's region.

|`files[].bucket`
|string
|Yes
|S3 bucket name

|`files[].key`
|string
|Yes
|S3 object key (path to the file)

|`output_format`
|string
|No
|Output format for the response: `json` (default), `markdown`, `html`, `yaml`, `text`, `doctags`

|`additional_formats`
|array
|No
|Additional formats to save back to S3. Each format is saved with the original key plus extension (e.g., `doc.pdf.md`).

|`options`
|object
|No
|Conversion options (see <<OCR Options>> below)
|===

=== OCR Options

The `options.ocr` object controls OCR behavior. By default, OCR is disabled. To enable OCR, specify an engine:

[source,json]
----
{
    "options": {
        "ocr": {
            "engine": "rapidocr",
            "force_full_page_ocr": false,
            "bitmap_area_threshold": 0.05,
            "lang": ["english", "chinese"]
        }
    }
}
----

[cols="1,1,1,3"]
|===
|Field |Type |Default |Description

|`engine`
|string
|`none`
|OCR engine to use: `none` (default), `rapidocr`, `easyocr`, `tesseract`, `tesseract_cli`, `textract`, `ocrmac`

|`force_full_page_ocr`
|boolean
|`false`
|If true, OCR is applied to the entire page regardless of detected text

|`bitmap_area_threshold`
|float
|`0.05`
|Percentage of page area (0.0-1.0) for a bitmap to trigger OCR processing

|`lang`
|array
|varies
|List of languages for OCR. Format depends on the engine.

|`aws_region`
|string
|env default
|AWS region for Textract (only for `aws_textract` engine)

|`use_gpu`
|boolean
|null
|Enable GPU acceleration (only for `easyocr` engine)

|`tesseract_cmd`
|string
|null
|Path to tesseract executable (only for `tesseract_cli` engine)

|`tesseract_psm`
|integer
|null
|Tesseract Page Segmentation Mode 0-13 (for `tesseract` and `tesseract_cli` engines)
|===

==== OCR Engine Options

[cols="1,3,2"]
|===
|Engine |Description |Default Languages

|`none`
|Disable OCR entirely
|N/A

|`rapidocr`
|Fast, lightweight OCR (recommended)
|`["english", "chinese"]`

|`easyocr`
|GPU-accelerated, many languages
|`["fr", "de", "es", "en"]`

|`tesseract`
|Tesseract via tesserocr library
|`["fra", "deu", "spa", "eng"]`

|`tesseract_cli`
|Tesseract via command line
|`["fra", "deu", "spa", "eng"]`

|`textract`
|AWS Textract (cloud-based, auto-detects language)
|Auto-detected

|`ocrmac`
|macOS native OCR (macOS only)
|`["fr-FR", "de-DE", "es-ES", "en-US"]`
|===

== Response Format

=== JSON Output (default)

Returns an array of conversion results:

[source,json]
----
[
    {
        "filename": "document.pdf",
        "status": "success",
        "document": { ... },
        "errors": [],
        "output": null,
        "output_format": "json",
        "saved_files": {
            "markdown": "s3://my-bucket/documents/file.pdf.md",
            "html": "s3://my-bucket/documents/file.pdf.html"
        }
    }
]
----

The `saved_files` field is only present when `additional_formats` was specified in the request, and contains a mapping of format names to S3 URIs where the converted files were saved.

=== Non-JSON Output

For other formats (`markdown`, `html`, `yaml`, `text`, `doctags`), returns the converted content directly as a string with the appropriate `Content-Type` header.

NOTE: When using non-JSON output formats, the `saved_files` information is not included in the response body. Use JSON output format if you need to know where additional formats were saved.

==== Save Additional Formats to S3

Convert a document and save markdown and HTML versions back to S3:

[source,bash]
----
curl -X POST "http://localhost:9000/2015-03-31/functions/function/invocations" \
    -H "Content-Type: application/json" \
    -d '{
        "files": [
            {
                "bucket": "my-documents-bucket",
                "key": "documents/contract.pdf"
            }
        ],
        "output_format": "json",
        "additional_formats": ["markdown", "html", "text"]
    }'
----

This will:

1. Convert the document and return JSON in the response
2. Save `documents/contract.pdf.md` (Markdown) to S3
3. Save `documents/contract.pdf.html` (HTML) to S3
4. Save `documents/contract.pdf.txt` (plain text) to S3

The response will include `saved_files` with the S3 URIs of the saved files.

== AWS Lambda Deployment

=== IAM Policy

The Lambda function requires read access to the S3 buckets containing documents. If using `additional_formats`, write access is also required:

[source,json]
----
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:GetObject",
                "s3:HeadObject",
                "s3:PutObject"
            ],
            "Resource": [
                "arn:aws:s3:::my-documents-bucket/*",
                "arn:aws:s3:::other-bucket/*"
            ]
        }
    ]
}
----

NOTE: `s3:PutObject` is only required if you use the `additional_formats` feature to save converted files back to S3.

For AWS Textract OCR support, add:

[source,json]
----
{
    "Effect": "Allow",
    "Action": [
        "textract:DetectDocumentText",
        "textract:AnalyzeDocument"
    ],
    "Resource": "*"
}
----

=== Deploying to AWS Lambda via ECR

==== Prerequisites

* AWS CLI configured with appropriate credentials
* Docker installed and running
* An ECR repository created for the Lambda image

==== Step 1: Create ECR Repository (if not exists)

[source,bash]
----
# Set variables
AWS_REGION=us-west-2
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
ECR_REPO_NAME=docling-lambda

# Create the repository
aws ecr create-repository \
    --repository-name $ECR_REPO_NAME \
    --region $AWS_REGION \
    --image-scanning-configuration scanOnPush=true
----

==== Step 2: Build and Push Docker Image

[source,bash]
----
# Set variables
AWS_REGION=us-west-2
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
ECR_REPO_NAME=docling-lambda
IMAGE_TAG=latest

# Authenticate Docker to ECR
aws ecr get-login-password --region $AWS_REGION | \
    docker login --username AWS --password-stdin $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com

# Build the image (from repository root)
# Use --platform linux/amd64 to ensure compatibility with Lambda (required on Apple Silicon Macs)
docker build --platform linux/amd64 -t $ECR_REPO_NAME:$IMAGE_TAG -f lambda/Dockerfile .

# Tag for ECR
docker tag $ECR_REPO_NAME:$IMAGE_TAG \
    $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPO_NAME:$IMAGE_TAG

# Push to ECR
docker push $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPO_NAME:$IMAGE_TAG
----

==== Step 3: Create IAM Role for Lambda

[source,bash]
----
# Create the trust policy
cat > trust-policy.json << 'EOF'
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "Service": "lambda.amazonaws.com"
            },
            "Action": "sts:AssumeRole"
        }
    ]
}
EOF

# Create the role
aws iam create-role \
    --role-name docling-lambda-role \
    --assume-role-policy-document file://trust-policy.json

# Attach basic Lambda execution policy
aws iam attach-role-policy \
    --role-name docling-lambda-role \
    --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole

# Create and attach S3 access policy
cat > s3-policy.json << 'EOF'
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:GetObject",
                "s3:HeadObject",
                "s3:PutObject"
            ],
            "Resource": [
                "arn:aws:s3:::*/*"
            ]
        }
    ]
}
EOF

aws iam put-role-policy \
    --role-name docling-lambda-role \
    --policy-name S3AccessPolicy \
    --policy-document file://s3-policy.json

# Clean up temp files
rm trust-policy.json s3-policy.json
----

==== Step 4: Create Lambda Function

[source,bash]
----
# Set variables
AWS_REGION=us-west-2
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
ECR_REPO_NAME=docling-lambda
IMAGE_TAG=latest
FUNCTION_NAME=icg-document-enrichmen

# Create the Lambda function
aws lambda create-function \
    --function-name $FUNCTION_NAME \
    --package-type Image \
    --code ImageUri=$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPO_NAME:$IMAGE_TAG \
    --role arn:aws:iam::$AWS_ACCOUNT_ID:role/docling-lambda-role \
    --timeout 300 \
    --memory-size 3008 \
    --region $AWS_REGION \
    --architectures x86_64
----

==== Step 5: Update Lambda Function (for subsequent deployments)

[source,bash]
----
# Set variables
AWS_REGION=us-west-2
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)

aws lambda update-function-code \
    --function-name $FUNCTION_NAME \
    --image-uri $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPO_NAME:$IMAGE_TAG \
    --region $AWS_REGION
----

==== Quick Deploy Script

Create a script `deploy.sh` in the `lambda/` directory for quick deployments:

[source,bash]
----
#!/bin/bash
set -e

AWS_REGION=${AWS_REGION:-us-west-2}
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
ECR_REPO_NAME=${ECR_REPO_NAME:-docling-lambda}
IMAGE_TAG=${IMAGE_TAG:-latest}
FUNCTION_NAME=${FUNCTION_NAME:-icg-document-enrichmen}

echo "Building Docker image..."
docker build --platform linux/amd64 -t $ECR_REPO_NAME:$IMAGE_TAG -f lambda/Dockerfile .

echo "Authenticating to ECR..."
aws ecr get-login-password --region $AWS_REGION | \
    docker login --username AWS --password-stdin $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com

echo "Tagging and pushing image..."
docker tag $ECR_REPO_NAME:$IMAGE_TAG \
    $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPO_NAME:$IMAGE_TAG
docker push $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPO_NAME:$IMAGE_TAG

echo "Updating Lambda function..."
aws lambda update-function-code \
    --function-name $FUNCTION_NAME \
    --image-uri $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPO_NAME:$IMAGE_TAG \
    --region $AWS_REGION

echo "Deployment complete!"
----

== Error Responses

Errors are returned with appropriate HTTP status codes:

[source,json]
----
{
    "statusCode": 400,
    "headers": {"Content-Type": "application/json"},
    "body": "{\"error\": \"At least one file must be provided in 'files' array\"}"
}
----

=== Common Error Codes

[cols="1,3"]
|===
|Status Code |Description

|400
|Bad request (missing files, invalid format, file too large)

|403
|Access denied to S3 object

|404
|S3 object not found

|500
|Internal conversion error
|===

== Limits

- Maximum 10 files per request
- Maximum 100MB per file
- Lambda timeout and memory limits apply (configure based on document complexity)

== Supported Input Formats

- PDF (`.pdf`)
- Microsoft Word (`.docx`)
- Microsoft PowerPoint (`.pptx`)
- Microsoft Excel (`.xlsx`)
- Images (`.png`, `.jpg`, `.jpeg`, `.tiff`, `.bmp`)
- HTML (`.html`)
- Markdown (`.md`)
- AsciiDoc (`.adoc`)
- CSV (`.csv`)
